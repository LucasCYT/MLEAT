ML-EAT - analysis code
======================

Repository: https://github.com/LucasCYT/MLEAT   (license: MIT, see LICENSE)

Code accompanying "ML-EAT: a permutation-based machine-learning framework for
predictive-contribution variant prioritization complementary to GWAS,
benchmarked on height in Taiwan Biobank."

ML-EAT ranks variants by their incremental predictive contribution to standing
height (add-one dMSE). It applies two data-driven thresholds: a Kneedle knee
point (prioritization set) and a permutation-based empirical FDR
(high-confidence set). It then benchmarks the ranking against an established
height GWAS (Yengo et al. 2022), assesses novelty, compares with a
cofactor-adjusted GWAS, and evaluates out-of-sample polygenic scores.


1. SCOPE OF THIS RELEASE
------------------------

This release covers the whole analysis, following the four steps of the paper
(Figure 1) and the out-of-sample polygenic-score (PGS) validation:

  Step 1  Baseline model construction                [00: S01, mleat_core.py]
          Sex-specific LASSO baseline model (BM) for standing height built
          from the prespecified non-genetic TWB cofactors + PC1-PC20; LASSO
          feature selection retains 32 (female) / 27 (male) BM features.

  Step 2  Add-one SNP testing and dMSE ranking       [00: S02]
          Each of the 510,274 SNPs is added individually to the BM; its
          incremental predictive contribution is the reduction in held-out
          test MSE (dMSE). SNPs are ranked genome-wide by dMSE.

  Step 3  ML-EAT adaptive prioritization              [00: S03, S04; 01]
          (a) Kneedle knee point on the ranking -> prioritization set
              (1,048 female / 378 male variants).
          (b) Genotype permutation of SNPs sampled from the top, middle and
              bottom strata -> empirical null -> genome-wide empirical FDR;
              FDR <= 5% -> high-confidence set (84 female / 19 male).

  Step 4  Benchmarking                                [01, 02, 04]
          Comparison with established height loci (Yengo et al. 2022;
          direct, LD-proxy and +-500 kb regional matching), rank-dependent
          enrichment, GWAS Catalog enrichment, novelty assessment and
          functional annotation, and concordance with a cofactor-adjusted
          GWAS run in the same TWB cohort.

  PGS     Out-of-sample polygenic-score validation   [02, 03, 04]
          Within the single 80/20 split, three panels (GWAS-significant,
          ML-EAT training-partition, high-confidence) are LD-reduced,
          weighted by training-partition GWAS effect sizes and scored in the
          20% held-out test partition (Pearson r, incremental R^2, AUROC,
          decile means; Table 1, Figure 5, Figure S3).

The upstream step (folder 00_baseline_addone_permutation/) comprises
baseline-model (BM) construction, the genome-wide add-one screen and the
genotype-permutation null. It was run on the NCHC HPC cluster against the
individual-level Taiwan Biobank (TWB) data, which cannot be redistributed. The
scripts are included so the procedure can be inspected and re-run after TWB
data access is granted. Their per-SNP outputs are the inputs to folders 01-04
(see Section 2). For each SNP, the add-one step fits the baseline covariate
model (non-genetic cofactors + PC1-PC20) plus that single SNP on the 80%
training partition and evaluates it on the 20% held-out test partition. The
null is generated by permuting that SNP's genotype within the training
partition while the phenotype and all covariates are held fixed.


2. REQUIRED INPUTS (PRODUCED UPSTREAM)
--------------------------------------

{sex}_cv_5_lasso_aligned_merged_20260702.csv            (used by 01, 03)
    Per-SNP ranking. Columns: Feature (rsID), lasso_mse_test (held-out 20%
    test MSE), lasso_mse_cv (5-fold CV MSE within the 80% training
    partition). A baseline row has Feature == 'basic'.

Genotype-permutation null files                          (used by 01)
    Per-SNP permuted MSE (permutation_id 0 = observed, > 0 = null), pooled
    across the top/middle/bottom strata (3.0 x 10^6 female / 9.0 x 10^5 male
    null values).

GIANT_HEIGHT_YENGO_2022_GWAS_SUMMARY_STATS_{ALL,EAS}.gz (used by 01, 04)
    Established-locus reference (RSID, CHR, POS, P).

{sex}_TopSNP_*.mtx                                       (used by 01)
    Genotype dosage matrix (pid + rsID_allele columns, values 0/1/2) for LD
    r^2 in the novelty step. Population-level LD (all participants).

TWB genotypes + per-sex covariate files                  (used by 02)
    PLINK inputs for the cofactor-adjusted GWAS (full cohort) and the
    training-partition GWAS (80%).


3. PIPELINE AND FOLDERS
-----------------------

3.0  00_baseline_addone_permutation/  -  Steps 1-3, upstream (HPC)

All models use a single 80/20 split (random_state = 42), a StandardScaler
fitted on the training partition, and LASSO with alpha = 0.01 (the value
selected by the baseline-model alpha scan, S01, and then fixed for every
subsequent model). They report the held-out test MSE (lasso_mse_test) and the
5-fold CV MSE within the training partition (lasso_mse_cv). S02 is the
original genome-wide add-one script. S03 shares mleat_core.py, so its observed
fit (permutation_id 0) and every permutation refit use the identical model.
Participants with no-call genotypes were removed before these steps.

  S01_baseline_model_alpha_scan.py
      Baseline model (Figure 2). LASSO alpha scan (25 values, 1e-5 to 10) on
      the candidate cofactors + PC1-PC20. Reports 5-fold CV R^2 in the 80%
      training partition and MSE/R^2 in three non-overlapping subsets of the
      20% test partition. Run on the full candidate set (37 female / 33 male),
      then on the retained features (32 female / 27 male = BM).
      In:  per-sex cofactor table
      Out: *_lasso_results.csv, *_lasso_feature_importance.csv

  mleat_core.py
      BM feature lists (32 female / 27 male), the split, and fit_and_score()
      (used by S03).

  S02_addone_screen.py
      Add-one screen (Step 2; cleaned from twb_lassoLoop_0612.py). BM + one
      SNP per fit, for every SNP in the analysis matrices, plus a BM-only row
      ('basic_columns').
      In:  height_merged_{sex}_mtx*.csv blocks
      Out: {file}_lasso_results.csv (index, columns, lasso_mse_cv,
           lasso_mse_test); concatenated over blocks =
           {sex}_cv_5_lasso_aligned_merged_20260702.csv

  S03_genotype_permutation_null.py
      Genotype-permutation null (Step 3). For each stratum SNP, permutation_id
      0 is the observed fit; ids 1-1000 permute the SNP within the training
      partition only (numpy RandomState(k)), with the phenotype, BM features
      and test partition held fixed.
      In:  *.mtx.csv + strata/*.csv
      Out: permutation_{sex}/{SNP}.csv
           (permutation_id, mse, mse_cv, permuted_snp_train_value)

  S04_merge_permutation_null.py
      Merges the per-SNP files of one stratum into the wide null table read by
      folder 01 (--perm-null).
      In:  permutation_{sex}/
      Out: {Top,Middle,Last}{1000,300}_{sex}_snps_merged.csv

  strata/
      SNPs sampled for the permutation null, by dMSE rank (M = 510,274 ranked
      SNPs).
        Top:    ranks 1-1,000 (female) / 1-300 (male)
        Middle: 1,000 / 300 SNPs from the middle of the ranking
                (ranks 173,085-300,921 female; 181,996-288,841 male)
        Last:   the 1,000 / 300 lowest-ranked SNPs

  slurm/
      SLURM job templates (NCHC partition ngs186G: 28 cores, 175 GB) for S02
      and S03.


3.0b demo/  -  end-to-end demonstration on synthetic data

Because the TWB individual-level data cannot be shared, a fully synthetic data
set with the same layout is provided for testing the code. It is generated
from random numbers with a fixed seed; no TWB data were used, sampled or
perturbed, and the SNP identifiers (rsSIM00001_A, ...) are fictitious.

  make_synthetic_data.py
      3,000 female / 2,500 male synthetic participants with the TWB cofactor
      names, PC1-PC20 and 600 SNPs; 10 causal SNPs (0.8-1.6 cm per allele)
      and 3 high-LD proxy SNPs shared by both sexes; a mock reference GWAS
      in which 7 of the causal SNPs are "established".
  make_ranking_and_strata.py
      Concatenates the S02 output into the ranking file and draws the
      Top / Middle / Last permutation strata.
  run_demo.sh
      Runs Step 1 (S01), Step 2 (S02), Step 3 (Kneedle; S03 + S04 with 20 SNPs
      per stratum and 50 permutations) and the FDR / enrichment step of
      folder 01 for both sexes, then compares the results with the simulated
      truth (summarize_demo.py). About 8 minutes on a laptop.
  expected_summary.txt
      Output of summarize_demo.py from a reference run.

Usage:  bash demo/run_demo.sh
In the reference run the 10 strongest variants of the ranking were causal or
proxy SNPs, and every member of the FDR <= 5% high-confidence set (4 female /
5 male) was a simulated causal or proxy SNP, while the broader Kneedle
prioritization set (10 / 16) contained most causal SNPs. Folders 02-04 need
PLINK genotype files and external references and are not part of the demo.


3.1  01_prioritization_and_fdr/  -  Step 3-4 core

  kneedle_prioritization.py
      Prioritization set. Kneedle maximum-distance knee point on the ordered
      held-out MSE placed at normal-quantile coordinates.
      In:  ranking CSV
      Out: *_prioritization_set.txt. Reproduces 1,048 (female) / 378 (male).

  mleat_downstream_analysis.py
      Empirical FDR + enrichment + novelty. FDR(t) = M * p0(t) / R(t) from the
      pooled permutation null; quartile enrichment (Cochran-Armitage);
      three-tier novelty (direct / LD-proxy r^2 >= 0.2 / +-500 kb regional).
      In:  ranking + null + Yengo (+ --geno dosage, --knee)
      Out: FDR curve, high-confidence set (84 female / 19 male), enrichment
           table.

  novelty_screen_FDRset_20260731.py
      Reference implementation of the permutation FDR + high-confidence-set
      novelty screen. The pooled null must exclude permutation_id == 0.
      In:  ranking + null
      Out: high-confidence set + novelty verdicts.

  FDR_methods_appendix.md
      Written derivation of the empirical-FDR estimator.


3.2  02_gwas/  -  cofactor-adjusted and training-partition GWAS (comparator)

PLINK v1.9 --linear wrappers. The same script is run per sex with the relevant
covariate file: the full cohort (cofactor-adjusted GWAS -> concordance,
lambda, Bonferroni/BH) and the 80% training partition (training-partition
GWAS -> PGS GWAS-significant panel, Figures S2/S4). Covariates = the ML-EAT
baseline cofactors + PC1-PC20 (33 female / 29 male).
Files: GWAS_female_c37.py, GWAS_male_c33.py, GWAS_male_c27.py,
       GWAS_female_outPCA.py, t3_runnung.sh


3.3  03_pgs/  -  out-of-sample polygenic scores (Step 4 predictive validation)

  S01_prepare_inputs.py
      Assembles test-partition phenotypes and per-panel inputs.
  S07_make_trainCV_panel.py
      ML-EAT training-partition panel: top-K by 5-fold-CV dMSE within the 80%
      training partition (K = prioritization-set size), never touching the 20%
      test partition.
  S09_make_weights_from_clumped.py
      Builds --score weight files from LD-clumped panels (training-partition
      GWAS beta).
  S08_plink_trainCV_panel.sh
      PLINK --clump / --score for the panels.
  S02_prs_benchmark_metrics.py
      PGS metrics: Pearson r (Fisher-z CI), incremental R^2, beta/SD, AUROC
      (DeLong), decile means; paired bootstrap. Produces the Table 1 /
      Figure 5 numbers.
  S06_leakage_null_simulation.py
      Null simulation showing that in-sample selection inflates the
      held-out-defined panels (motivates the training-partition panel).


3.4  04_benchmarking_and_figures/  -  enrichment, novelty and figures

Figure 4 / Figure S1 (GWAS-Catalog enrichment of the dMSE ranking; S01-S03),
refcount enrichment and gene-level overlap statistics (S04-S06: hypergeometric
+ Fisher), ML-vs-GWAS rank comparison and recall AUROC (S07-S09),
candidate-novel support and unexplored-loci scan (S10-S11), and the Figure 5 /
S3 PGS plots (S03_make_Fig5.py, S04_make_FigS3.py).


4. SOFTWARE
-----------

Python 3 with NumPy, pandas, SciPy, scikit-learn (LASSO / model fitting) and
Matplotlib; PLINK v1.9 for genotype processing, GWAS (--linear), LD
clumping/pruning and scoring. Knee-point detection uses a NumPy/SciPy
implementation of the Kneedle maximum-distance criterion
(01_prioritization_and_fdr/kneedle_prioritization.py), not an external
knee-point package.


5. REPRODUCIBILITY NOTES
------------------------

- The single 80/20 split uses random_state = 42 throughout (BM, add-one, PGS).
- kneedle_prioritization.py reproduces the published prioritization-set sizes
  (1,048 female / 378 male) on the 2026-07-02 rankings.
- The permutation-FDR pooled null must exclude the observed row
  (permutation_id == 0).
- TWB genotype/phenotype data are available from the Taiwan Biobank under
  application; they are not redistributed here.
- Cluster-specific paths and account names in the job scripts (02_gwas/,
  03_pgs/S08, 00_*/slurm/) are replaced by placeholders (/path/to/...,
  <ACCOUNT>); edit them for your system.
- The pipeline can be tested without TWB data with demo/run_demo.sh.
